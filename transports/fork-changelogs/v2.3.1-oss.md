- **Upstream Synchronization** - Rebased the ten active fork patch branches onto upstream `main` at `4de5eafcc`, which includes transport `v2.3.0` and `v2.3.1`. The release is cut from that anchor, so it also carries the upstream commits merged after the `transports/v2.3.1` tag.
- **Responses-to-Chat Compatibility** - `compat.convert_responses_to_chat` now sits beside upstream's new `force_reasoning_only_models_to_responses` and `convert_decision_to_responses` toggles, is registered in the configstore migration table, and is applied by the post-save compat reload. Its documentation moved to section 5 of the compat plugin page so upstream's section anchors stay unchanged.
- **Custom Provider Bases** - Z.AI, Zhipu and CLI Proxy API are now accepted as `base_provider_type` by the core provider factory, not only by the config schema. Custom providers keep their own identity, and the UI offers Z.AI and Zhipu as base providers with their supported request types.
- **Fork Providers** - SiliconFlow, SiliconFlow CN, DeepInfra, Z.AI, Zhipu and CLI Proxy API implement upstream's new model-retrieve operation as unsupported, and their tests follow upstream's `SecretVar` extra-header and embedding-input shapes.
- **Streaming Drain** - The generic stream reader still records end-of-body through the reserved-write path. Upstream's own marker covers only the OpenAI raw-stream paths, so streams on other providers no longer deadlock on drain.
- **Release Notes** - Fork release bodies now append notes from `transports/fork-changelogs/<tag>.md`, and one-line Markdown comments no longer strip the rest of a changelog.
- **Documentation** - The config schema reference lists the fork provider keys `siliconflow`, `siliconflow-cn`, `zai`, `zhipu` and `cpa`.
- **Multinode Patch Isolation** - The optional PostgreSQL revision/CAS configuration-sync patch is still excluded from this integration and kept separately on `feat/oss-multinode-config-sync`.
